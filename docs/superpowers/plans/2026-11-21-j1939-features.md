# j1939-rs Feature Expansion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add transport protocol (TP), not-available/error signal values, big-endian fields, multiplexed + DM1 messages, and `defmt`/single-frame guards to j1939-rs.

**Architecture:** Everything runtime lives in `j1939-core` (`no_std`, allocation-free, `forbid(unsafe_code)`); the macros only parse new attributes and emit calls into core. TP is a sans-io state machine (caller supplies frames and a `now_ms: u32` clock, gets frames back), so it works with any CAN driver and is testable without hardware. Each Part is independently shippable and ordered so later Parts can use earlier ones (Part 5's DM1 is tested over Part 4's TP).

**Tech Stack:** Rust 1.88+ (edition 2024), `syn`/`quote` proc macros, `trybuild` compile-fail tests, `proptest`, optional `embedded-can 0.4`, optional `defmt 1`.

**Spec:** Feature list agreed in the conversation of 2026-11-21 (items 1, 2, 3, 5, 7: TP, NA/error values, big-endian, multiplexed/variable-length with DM1, `defmt` + compile-time single-frame check). Item 4 (address claim) and 6 (DBC generation) are out of scope. Design decisions made while planning are in "Design Decisions" below; the executor should not re-litigate them.

## Global Constraints

- `j1939-core` and all macro-generated code stay `#![no_std]` and allocation-free; no `alloc`, no `heapless` dependency.
- `#![forbid(unsafe_code)]` on every crate.
- Must build for `thumbv6m-none-eabi` (Cortex-M0+, no FPU): `cargo build -p j1939-core --target thumbv6m-none-eabi`, also with each new feature enabled, and `cargo build -p j1939-nostd-check --target thumbv6m-none-eabi`.
- `rust-version = "1.88"`; no APIs newer than that.
- `cargo test --workspace --all-features`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, `cargo fmt --all -- --check`, and `RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps --all-features` must be clean at the end of every task.
- `J1939Message::MAX_LENGTH` stays 223; `J1939Message::length` stays `u16`.
- Float-to-raw conversion keeps saturating and uses `core`-only helpers (no `f32::round`).
- TDD: every task starts with a failing test that is run and seen to fail for the stated reason.
- New public fallible APIs return `j1939_core::Result`; new `Error` variants are added to the existing enum (it is not `#[non_exhaustive]`; a minor-version bump covers it).
- Version: if 0.2.0 has already been published, bump all crates to 0.3.0 in Task 12; otherwise keep 0.2.0 and extend its changelog entry.

## Design Decisions

- **TP scope:** BAM and RTS/CTS, both directions, one `TpRx<const SESSIONS: usize = 1>` session table. Reassembly capacity is `J1939Message::MAX_LENGTH` (223); a larger announced size gets an abort with reason `Resources` (the J1939-21 limit of 1785 is not buffered). ETP (PGN 0xC800/0xC700) is not implemented.
- **TP timing:** timers are constants in `tp::timing` (T1 750 ms, T2 1250, T3 1250, T4 1050, BAM inter-packet 50 ms); the caller passes `now_ms: u32`, compared with wrapping subtraction.
- **Signals:** opt-in through the field type `j1939_core::Signal<T>`; existing fields keep today's behaviour. Valid/special ranges follow J1939-71: for fields of 8+ bits the top byte of the field decides (`0xFF` not-available, `0xFE` error, `0xFB..=0xFD` reserved); for 2–7 bit fields the all-ones value is not-available, all-ones minus one is error. Unsigned integer and unsigned scaled fields only.
- **Big-endian:** `byte_order = "big"` per field; the `bits` range keeps the crate's bit numbering and must be byte-aligned (start and width multiples of 8); bytes are stored most-significant first. Unaligned Motorola (DBC `@0`) layouts are rejected at compile time.
- **Multiplexing:** a `#[j1939_mux]` enum whose variants wrap ordinary `#[j1939_message]` structs. The enum owns the selector bits; each variant struct marks them `reserved`. Unknown selector is an error, never a default.
- **Variable length:** hand-written `Dm1`/`Dm2` in core (`Dtc`, `LampStatus`) rather than a generic repeating-field macro (YAGNI until a second repeating message exists).
- **defmt:** `defmt` cargo feature derives `defmt::Format` on core types (manual impl for `J1939Message`, printing only `data[..length]`); generated message structs get it through an explicit `defmt` flag on `#[j1939_message]`, because a `cfg(feature)` emitted by a macro would be evaluated in the user's crate.

## Review Focus

Inputs and conditions the feature list implies but no obvious task test covers; each has a pinning test in the owning task (marked **RF**).

1. TP data packets arriving out of order, duplicated, or after the session timed out must abort the session with the right reason, not corrupt the buffer or hang. (Task 8)
2. A scaled/integer `Signal` value above the valid range must saturate to the largest *valid* raw value, never into the not-available/error codes. (Task 4)
3. A big-endian field that is not byte-aligned or whose width is not a multiple of 8 must be a compile error, not silently mis-encoded. (Task 5)
4. DM1 edge shapes: zero DTCs (the all-zero "no active DTC" record), exactly one DTC (padded to 8 bytes with `0xFF`), more DTCs than the `Dm1` capacity, and an odd payload length. (Task 10)
5. A mux message with an unknown selector, or a variant whose struct does not reserve the selector bits, must fail loudly. (Task 11)

### Task 8: RTS/CTS, aborts and timeouts

**Files:**
- Modify: `j1939-core/src/tp/{tx,rx}.rs`
- Test: `j1939-core/tests/tp_rts.rs`

**Interfaces:**
- Consumes: Tasks 6-7.
